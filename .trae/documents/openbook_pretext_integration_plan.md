# OpenBook - Pretext 集成改造计划

## 项目背景

OpenBook 是一个基于 Node.js 的 RSS 阅读器和知识收集器，提供统一的阅读和笔记界面。Pretext 是一个纯 JavaScript/TypeScript 库，用于多行文本测量和布局，避免使用 DOM 测量，而是使用 canvas 进行文本测量，提供更高效、准确的文本布局能力。

## 改造目标

1. 集成 Pretext 库到 OpenBook 项目中
2. 改进 OpenBook 的文本布局和测量功能
3. 提升用户阅读体验，特别是在长文本和响应式布局方面
4. 优化性能，减少 DOM 操作和重排

## 技术实现要点

1. **Pretext 集成**:
   - 使用 `npm install @chenglou/pretext` 安装库
   - 创建 `lib/pretext.js` 封装 Pretext 功能
   - 提供简单的 API 接口供前端使用

2. **前端改造**:
   - 修改 `public/js/reader.js` 使用 Pretext 进行文本布局
   - 修改 `public/js/notes.js` 使用 Pretext 计算笔记卡片高度
   - 优化响应式布局逻辑

3. **性能优化**:
   - 缓存 Pretext 的 `prepare()` 结果
   - 只在必要时重新计算布局
   - 使用防抖技术处理窗口 resize 事件

4. **测试策略**:
   - 编写单元测试验证 Pretext 集成
   - 进行性能测试比较改造前后的性能
   - 进行跨浏览器测试

## 预期收益

1. **性能提升**:
   - 减少 DOM 操作和重排
   - 更快的文本布局计算
   - 更流畅的用户体验

2. **功能改进**:
   - 更准确的文本高度计算
   - 更好的响应式布局
   - 支持更复杂的文本布局场景

3. **代码质量**:
   - 更清晰的布局逻辑
   - 更好的可维护性
   - 减少浏览器兼容性问题

## 风险评估

1. **兼容性风险**:
   - Pretext 可能在某些浏览器中存在兼容性问题
   - 需要进行充分的跨浏览器测试

2. **性能风险**:
   - 如果使用不当，Pretext 可能导致性能问题
   - 需要合理使用缓存和优化策略

3. **集成风险**:
   - 与现有代码的集成可能存在冲突
   - 需要仔细规划集成步骤
